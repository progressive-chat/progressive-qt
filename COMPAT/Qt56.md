# Qt 5.6 port notes (Spectral 464 → Progressive Chat Qt)

Base: Spectral tag 464, commit `8c29382b3eb7a24c5abe3196c78a546329bb75d9`
(Oct 2018). Upstream required Qt 5.10+ (`BUILD.md`).
Goal: build and run on **Qt 5.6**, desktop and **Android 4.0 (API 14) down
to 2.3 (API 9)**.

## What was changed

Upstream used Qt Quick Controls 2 + Material style (Qt >= 5.7), which do
not exist on Qt 5.6. All QML now targets **QtQuick 2.6 + Controls 1.4 +
Layouts 1.2** plus QtQuick-only custom components:

- QML imports downgraded: QtQuick 2.6, Controls 1.4, Layouts 1.2,
  Models 2.2, Window 2.0. No `QtQuick.Controls.Material`, no Controls 2.
- New `Progressive.Style` module (`PPalette` singleton): brand palette
  (primary `#344955`, accent `#498882`, dark/light variants) driven by
  `PSettings.darkTheme`. Replaces every `Material.*` reference.
- New `Progressive.Component` kit (pure QtQuick / Controls 1.4):
  `PButton` (accent button, `flat` variant), `PItemDelegate` (clickable
  row/icon, `contentItem` support), `PCircleButton` (round FAB),
  `PDialog` (modal centered dialog, optional buttons, outside-click close
  when buttonless), `PScreenStack` (push/pop/replace/clear/depth/
  currentItem/initialItem, used via `js/util.js`), `PDrawer` (right-edge
  slide-in panel).
- `Qt.labs.platform` (tray, StandardPaths, Qt >= 5.8 only) removed from the
  startup path: tray icon moved to `Progressive.Compat.TrayIcon`, loaded via
  `Loader` on non-Android desktop only; `DownloadableContent` uses the
  `cacheLocation` context property from C++ `QStandardPaths`.
- `Qt.labs.settings` removed: `Progressive.Setting` singleton is
  LocalStorage-backed with the same keys (`showTray`, `confirmOnExit`,
  `darkTheme`, `pressAndHold`, plus `richText`).
- `Shortcut` (uncertain pre-5.6 availability) replaced: Return-to-login via
  `TextField.accepted`, Ctrl+F shortcut dropped. `ToolTip` replaced with
  inline labels. `Switch` replaced with `CheckBox`. `Dialog`/`Popup`/
  `Drawer`/`Page`/`Pane`/`RoundButton`/`ToolButton`/`ItemDelegate`/
  `StackView`/`ScrollBar` replaced as above. `Timer.triggeredOnStart`
  (Qt >= 5.8) replaced with an explicit first-fire in `RoomPanelInput`.
- Vendored `SplitView` (Qt's own Controls-1-era file, LGPL-3.0): dropped
  vestigial Controls 2 / `QtQuick.Window` imports; `Screen.pixelDensity`
  grab margin replaced with a fixed 8 px (no Window dependency).
- C++ kept portable: `PROGRESSIVE_NO_MULTIMEDIA` fallback when QtMultimedia
  is absent (audio playback becomes a warning); explicit `#include
  <QPainterPath>`; `std::hash<QString>` guard for Qt >= 5.14 (needed only
  below 5.14, i.e. including the 5.6 target).
- Android packaging: `android/AndroidManifest.xml` (minSdk 9 / targetSdk 14),
  density icons from the Progressive Chat brand avatar,
  `ANDROID_PACKAGE_SOURCE_DIR` wired in the `.pro`.
- QML modules renamed `Spectral.*` → `Progressive.*`, singleton
  `MSettings` → `PSettings`; icons replaced with the Progressive Chat brand
  avatar from `progressive-android`.

## Verification (this container: Qt 5.15, no Controls/Effects/Multimedia)

- `qmake progressive-qt.pro && make` clean (only lib deprecation warnings).
- Headless QML harness (`QQmlEngine`, offscreen): timeline delegates with
  fake roles, room/account delegates, full component kit — all load with
  zero errors/warnings (test-only QtQuick.Controls 1.4 / Styles 1.1 /
  QtGraphicalEffects stubs stand in for modules this container lacks; the
  real Qt 5.6 target ships them).
- Full app offscreen run: `main.qml` (login/room/setting pages, dialogs,
  menus, drawer) loads with zero errors; process stays resident. (One
  by-design warning remains here: `Qt.labs.platform` is not installed in
  this container — the tray `Loader` tolerates it, same as on Qt 5.6.)
- `rcc -binary res.qrc` passes (resource integrity).
- API audit against real Qt 5.6 sources (`qtquickcontrols` 5.6 branch):
  every Controls/Styles API used was verified present (Menu.popup,
  TextField echoMode/placeholderText/readOnly/accepted, TextArea
  readOnly/wrapMode/cursorPosition/frameVisible, ProgressBar.indeterminate,
  ButtonStyle/TextFieldStyle/ProgressBarStyle, Switch exists but CheckBox
  is used). This audit caught and fixed 3 real bugs: TextArea has no
  `placeholderText` on 5.6 (custom overlay label now), TextAreaStyle has
  neither `background` nor `padding` (uses `frameVisible: false` +
  geometry offset now), ScrollView has no `horizontalScrollBarVisible`
  (uses `horizontalScrollBarPolicy: Qt.ScrollBarAlwaysOff` now).

## Known remaining work

1. **On-device proof**: build with Qt 5.6.3 + NDK r10e, install on an
   Android 4.0 emulator, then 2.3 (API 9 needs a custom Qt build; Qt 5.6
   officially supports API 14+ — manifest already declares minSdk 9).
2. **Notifications on Android**: D-Bus/win32/mac managers excluded for
   `android` in the `.pro`; in-app banners are the fallback.
3. **C++ class names** `SpectralRoom`/`SpectralUser` kept for now to keep the
   diff reviewable; rename to `ProgressiveRoom`/`ProgressiveUser` later.
4. `imports/Progressive/Component/SplitView.qml` is LGPL-3.0 (Qt's own
   file, header kept); everything else is GPL-3.0-only.
